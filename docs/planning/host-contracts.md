# Host contracts for the `job-search` plugin

Checked 2026-10-01 against each host's own source or docs. Every adapter in `job-search/` cites a row here; when a host changes, update this file first, then the adapter and its test. "Unverified" means no primary source was reachable from the build container — do not treat it as known.

## Decisions locked from this table

1. **Host scope:** native adapters for Claude Code (+ claude.ai/Cowork format), Hermes, Pi, OpenCode, OpenClaw; MCP + `AGENTS.md` for the rest.
2. **Skill names stay kebab-case.** Hermes, OpenCode and the Agent Skills spec all require `^[a-z0-9]+(-[a-z0-9]+)*$` matching the directory, so synced library skills are renamed (`CreateSkill` → `create-skill`). Library frontmatter extras (`category`, `effort`, `domain`) are ignored by every host above; kept.
3. **Two MCP files, one server.** Claude reads `.mcp.json`; Hermes reads `mcp.json` (different schema). Both run `scripts/jobsearch mcp`. Neither file is read by the other host.
4. **The CLI is the universal surface.** Pi has no core MCP and Cowork is unverified, so every skill workflow must work through `jobsearch` alone; MCP is an optimisation for hosts that have it.
5. **OpenCode sees every `.claude/skills` and `.agents/skills` entry in the repo**, which is why consolidation (AP3) removes them from those paths rather than only adding a plugin.
6. **Data home** order: `JOB_SEARCH_HOME` → checkout `data/` when run from a checkout → `${XDG_DATA_HOME:-~/.local/share}/job-search`. Never `${CLAUDE_PLUGIN_DATA}` or Hermes `${PLUGIN_DATA}` for personal data.
7. **Legacy MCP tool names** behind `JOB_SEARCH_MCP_LEGACY=1` for one release.
8. **Launcher** in `scripts/`, not `bin/`.
